# UI Blocks

shadcn-styled page-builder components for Neleto — navigation, footer, hero,
sections and content blocks you can assemble into complete pages. Server-rendered
(Handlebars + namespaced CSS), self-contained, and driven by shadcn's neutral
design-token system (light + dark), with per-block accent and surface controls.

No React, no runtime Tailwind, no database — this is a **components-only** plugin
(`bin: "sleep infinity"`), mirroring the media-gallery plugin.

## Composition model

A page is a stack of blocks. The **Section** block is a real container — it sets
`canHaveChildren: true` and renders dropped blocks via
`{{ render_elements(children) }}`, so you can wrap a group of blocks in a
max-width band with its own surface / theme / accent and an optional anchor id:

```
Navigation  →  Section [ Hero, Feature Grid, CTA … ]  →  Footer
```

Standalone blocks also constrain their inner content to a shared `--sc-container`
max-width by default (with a full-bleed option), so page content stays aligned
whether or not it sits inside a Section.

> **Backend requirement:** the container Section needs a Neleto backend that reads
> `canHaveChildren` from a plugin component's `.meta.json`
> (`shared/src/model/element.rs` → `ComponentMetadataFromFile`). Older backends
> ignore the flag, so Section renders as a plain band that can't accept children.

## Theming

Design tokens live in `styles/base.css` (shadcn neutral, light + dark). Each block
carries a `data-sc-theme` control (`auto` / `light` / `dark`) and an optional
accent (`sc-accent-*`). Colors are stored as raw HSL channels so blocks compose
alpha, e.g. `hsl(var(--sc-border) / 0.6)`.

## Build & package

Component `style.css` is generated by concatenating `styles/base.css` with each
component's `part.css`, so the token base stays DRY:

```sh
just build      # regenerate every components/*/style.css
just package    # build, then plugin-cli package
```
